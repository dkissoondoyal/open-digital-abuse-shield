# ODAS v0.2.2 — Replay protection prototype

This experimental module adds HMAC-authenticated timestamps, 128-bit nonce
identifiers and persistent SQLite replay detection to the observation-only
gateway evidence model. A key ID enables staged key rotation.

## Threat model and limitations
- Gateway must generate nonces using a cryptographically secure random source
  and timestamps using a reliable clock. A verifier cannot enforce randomness.
- Trusted keys are provisioned outside untrusted messages, securely stored,
  rotated and revoked by the operator. Never commit real secrets.
- SQLite must be on a protected, persistent local filesystem. Shared network
  filesystems and distributed verifiers need a separate atomic shared store.
- The replay database grows without automatic pruning. Retention, clock rollback
  and disaster recovery require an explicit policy before production.
- A lost database allows old still-valid signed evidence to be replayed.
- Clock skew is limited to 30 seconds future, 300 seconds past.
- Key IDs are authenticated but keys themselves are not automatically rotated.
- This does NOT perform SPF/DKIM/DMARC verification, nor does it intercept,
  quarantine or reject email. It is not ready for production.
- Message size currently capped at 256 KB; this is an evidence prototype, not
  a full-message processing architecture.

## Security acceptance criteria for later work
Authenticated gateway transport, durable multi-instance replay store, key
lifecycle management, independently verified email authentication, replay
retention policy and false-positive shadow-mode metrics.
