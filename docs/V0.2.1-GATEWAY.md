# ODAS v0.2.1: Gateway evidence boundary (experimental)

This module authenticates a small evidence envelope with HMAC-SHA256 and
binds it to the exact message bytes using SHA-256. It does not verify SPF,
DKIM, DMARC or ARC itself, and does not integrate with any real mail server.

## Assumptions
- Only the authorised gateway and ODAS verifier know a unique random key.
- Keys are supplied by protected local configuration, never by an email,
  user-supplied JSON, or a public repository.
- The gateway computes authentication results independently, strips or
  distinguishes attacker-supplied Authentication-Results headers, and signs
  the envelope *after* computing the message hash.
- Both parties hash the same byte representation of the message.
- No untrusted web/API caller may select or replace trusted gateway keys.

## Security limitations
- HMAC provides integrity and authentication under a shared secret, but
  not non-repudiation.
- Replay is **not** prevented. A future transport adapter needs freshness,
  message identifiers, replay tracking and key rotation.
- A compromised gateway or key can submit false evidence.
- Hashing an entire email may expose sensitive content if logging is careless;
  never log message bodies or keys.
- Authenticated gateway claims are not independently verified DNS/crypto results.
- The verifier deliberately makes no block or quarantine decisions.

## Next acceptance criteria
Authenticated transport, rotation and replay defence; verified SPF/DKIM/DMARC
library integration; synthetic forwarding and mailing-list fixtures; documented
false-positive metrics in shadow mode.
