# ODAS v0.3 — Independent email authentication (development)

## First increment: DKIM
An optional dkimpy adapter provides cryptographic verification of a DKIM
signature using a caller-provided DNS TXT lookup. No live DNS resolver, SMTP
integration or automatic blocking is shipped. Unit tests use synthetic mocks;
passing tests does not demonstrate cryptographic interoperability.

## Next increments
1. Add genuine RFC-conformant signed DKIM fixtures and negative cases.
2. Implement a bounded, cache-aware DNS resolver with appropriate error handling.
3. Handle multiple signatures and report signing-domain identity.
4. Add SPF evaluation with authenticated SMTP envelope/IP context.
5. Add DMARC alignment and policy evaluation using validated SPF/DKIM results.
6. Evaluate forwarding, mailing lists and ARC before any enforcement design.

## Safety
DKIM pass does not imply benign content. DKIM fail may result from forwarding,
message modification or DNS errors. Remain observation-only; no quarantine or
rejection. Do not expose private message contents to external services.
