# ODAS v0.3 — Independent email authentication (experimental)

## Current implementation: DKIM observations
Optional dkimpy-backed cryptographic verification uses a caller-provided DNS TXT lookup. The implementation includes synthetic unit tests, genuine RSA cryptographic integration fixtures, per-signature observations and conservative DNS-error handling. No live DNS resolver, SMTP integration, automatic blocking, quarantine or rejection is shipped. A passing CI suite does not establish production security.

## Remaining development work
1. Specify and test a bounded, cache-aware DNS resolver contract, including timeouts, lookup budgets and failure handling.
2. Add adversarial tests for duplicate, malformed and folded headers, ambiguous signing domains and mixed multi-signature outcomes.
3. Review dependency versions, resource consumption, privacy and cryptographic error semantics.
4. Add SPF evaluation only with trusted SMTP envelope and connecting-IP context.
5. Add DMARC evaluation only with validated SPF/DKIM results and RFC5322.From alignment.
6. Evaluate forwarding, mailing lists and ARC before considering any enforcement architecture.

## Security and release gates
See [V0.3-SECURITY-REVIEW.md](V0.3-SECURITY-REVIEW.md) for the threat model, outstanding issues and checklist. PR #4 remains Draft until independent review and explicit maintainer approval.

DKIM pass does not imply benign content or verified sender identity. DKIM fail may result from forwarding, modification or DNS errors. Remain observation-only and do not expose private message contents to external services.
